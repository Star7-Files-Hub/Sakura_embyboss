# 播放速率限制

## 功能概述

播放速率限制（码率限制）通过 Emby 的**用户策略字段 `RemoteClientBitrateLimit`** 限制每个用户客户端的播放码率：超过上限时由 Emby 服务端限制/转码该播放流。

- 普通用户与白名单用户使用**两个独立的码率值**（单位 MB/s）
- **bot 管理员与 Emby 管理员始终不限速**（写 `0`），这个豁免没有开关
- 配置值 **`0` 表示不限速**，是合法取值，不是「未设置」
- 这是 **Emby 服务端策略**层面的限制，与「同时播放限制」的「检测到超限就终止流 + 警告 + 封禁」是两套完全不同的机制，详见下文对比

> ⚠️ **服务端前提**：本功能依赖 Emby 官方服务端实现 `POST /emby/Users/{id}/Policy`。
> 若你的站点使用的是**自研 go-emby 服务端**（`ProductName` 为 `Go Emby STRM`），
> 该接口是空转的（返回 204 但丢弃请求体），`RemoteClientBitrateLimit` 恒为 0，
> **本功能无法生效**。面板会直接提示「当前服务端不支持播放速率限制」。
> 详见 [go-emby 兼容性说明](Go_Emby_Compatibility.md)。

## 功能特性

- **双档码率**：普通用户与白名单用户各设一个上限（默认 8 MB/s 与 20 MB/s）
- **管理员豁免**：bot 管理员与 Emby 管理员一律不限速，硬编码、没有开关
- **0 = 不限速**：任意一档填 `0` 即对该类用户完全不限速
- **建档自动生效**：新用户创建时就按当时的配置写入策略
- **一键批量应用**：面板「⚡ 立即应用到全部用户」把当前配置刷到所有存量用户
- **幂等且安全**：批量应用只改 `RemoteClientBitrateLimit` 一个字段，已是目标值的用户直接跳过

## 配置说明

在 `config.json` 中添加以下配置项：

```json
{
  "playback_rate_limit_enabled": false,
  "playback_rate_limit": 8,
  "playback_rate_limit_whitelist": 20
}
```

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `playback_rate_limit_enabled` | bool | `false` | 是否启用播放速率限制；关闭时所有用户都不限速 |
| `playback_rate_limit` | int | `8` | 普通用户的码率上限（MB/s），`0` = 不限速 |
| `playback_rate_limit_whitelist` | int | `20` | 白名单用户（`lv: a`）的码率上限（MB/s），`0` = 不限速 |

> ⚠️ 面板输入的取值范围是 **0-999**。注意与「同时播放限制」的上限 **1-99** 不同：那边的下界是 1，这边 `0` 是有意义的取值（不限速）。

## 换算规则

Emby 的 `RemoteClientBitrateLimit` 字段单位是 **bit/s**，而配置项的单位是 **MB/s**，换算关系：

```
bit/s = MB/s × 8 × 1024 × 1024          （1 MB = 1024 × 1024 字节）
```

| 配置值（MB/s） | 写入 Emby 的值（bit/s） | 说明 |
|---|---|---|
| `0` | `0` | 不限速 |
| `1` | `8388608` | 最小的非 0 限速值 |
| `8` | `67108864` | 普通用户默认值 |
| `20` | `167772160` | 白名单默认值 |
| `50` | `419430400` | 举例 |
| `999` | `8380219392` | 面板允许的最大值 |

**具体例子**：

- 8 MB/s → `8 × 8 × 1024 × 1024 = 67108864` bit/s
- 20 MB/s → `20 × 8 × 1024 × 1024 = 167772160` bit/s

自查是否生效：在 Emby 后台查看该用户的策略，`RemoteClientBitrateLimit` 应当等于上表换算出来的值；bot 面板的子页也会把每个值同时显示成 `N MB/s（M bit/s）`。

## 生效时机

| 场景 | 是否需要手动操作 |
|---|---|
| **新用户建档** | 不需要，创建时自动按当时的配置写入策略 |
| **存量用户**（已存在） | **需要**：点面板「⚡ 立即应用到全部用户」 |
| 改了码率值、或拨动总开关之后 | 存量用户需要再点一次「⚡ 立即应用到全部用户」 |
| 关闭开关后想解除已有用户的限速 | 先关闭开关，**再**点「⚡ 立即应用到全部用户」；此时目标值为 `0`，存量用户会被改成不限速 |

- 批量应用是**幂等**的：已经是目标码率的用户会被跳过（不发请求），面板会如实报告成功/失败/未改动，不会把「全部已是最新值」说成失败。
- 批量应用**只改 `RemoteClientBitrateLimit` 一个字段**：取回用户现有策略、只覆盖这一个键后原样写回，因此不会动其它权限，也不会把 Emby 管理员降权。
- 管理员（bot 管理员 + Emby 管理员）在批量应用时被写成 `0`（不限速）。
- 拿不到某个用户的现有策略时会**跳过**该用户（绝不写入空策略），并在日志里记一条 warning。
- 批量应用会对每个用户发一次请求，用户多时耗时较长，面板会先提示「正在应用，请稍候」。

## 控制面板操作

`/config` → **✅ 播放速率限制** / **❎ 播放速率限制**（主面板按钮，标签直接反映总开关状态）

进入后是子面板 **🎬 播放速率限制设置**，正文会显示当前状态、普通用户码率、白名单码率（每个都同时给出 MB/s 与 bit/s），以及换算规则、豁免说明和生效时机。

| 按钮 | 作用 |
|---|---|
| `✅ 播放速率限制` / `❎ 播放速率限制` | 打开 / 关闭总开关 |
| `设置普通用户码率(N MB/s)` | 输入 0-999，设置普通用户码率 |
| `设置白名单码率(N MB/s)` | 输入 0-999，设置白名单码率 |
| `⚡ 立即应用到全部用户` | 把当前配置刷到所有存量 Emby 用户 |
| `🔙 返回` | 返回上层面板 |

> 📌 与「同时播放限制」的开关不同，本功能的开关只有 `✅` / `❎` 两种状态，没有「已开启但未生效」的中间态：它不依赖定时任务，新用户建档即生效、存量用户靠「立即应用」。

## 与「同时播放限制」的区别

这是两套**完全不同**的机制，经常被混为一谈：

| | 播放速率限制（本页） | 同时播放限制 |
|---|---|---|
| 作用层 | **Emby 服务端用户策略**（`RemoteClientBitrateLimit` 字段） | bot 定时检测 + 调用 Emby API |
| 限制对象 | 单个播放流的**码率 / 画质** | 同一用户的**并发播放流数量** |
| 触发方式 | Emby 自己执行，播放时即生效 | bot 按检测间隔轮询 `/emby/Sessions` |
| 超限后果 | Emby 限制 / 转码该播放流（不封号、不打扰用户） | 终止该用户所有播放流 + 私信警告 + 群内通报，累计超过阈值后**封禁账号** |
| 豁免规则 | bot 管理员、Emby 管理员一律不限速（硬编码） | bot 管理员永久豁免；白名单默认豁免，可在面板开关后按独立上限判定 |
| 对存量用户 | 需要点「⚡ 立即应用到全部用户」 | 下一个检测周期自动生效 |
| 配置项前缀 | `playback_rate_limit*` | `concurrent_play_limit*` |

两者可以同时开启，互不影响。

## 已知边界

- **不在 bot 数据库里的 Emby 账号**（例如直接建在 Emby 侧）会被当作**普通用户**处理：批量应用时按 `playback_rate_limit` 写入，日志里会记一条「未找到对应的 bot 用户记录，播放速率限制按普通用户处理」的 warning。
- 配置值非法（不是整数）时按**不限速**处理，并记一条 warning；配置值小于等于 0 时同样是不限速。
- 码率上限是**服务端策略**，客户端仍可主动选择更低码率播放；本功能只设上限，不提升画质。

## 常见问题

**Q：我把码率设成 0 了，是不是没配置成功？**

A：不是。`0` 是合法取值，表示**不限速**，面板上会显示成 `0 MB/s（不限速）`。

**Q：改了码率，为什么现有用户没变化？**

A：配置只影响之后新写入的策略。存量用户必须点面板的「⚡ 立即应用到全部用户」才会生效。

**Q：关闭开关后，之前被限速的用户会自动恢复吗？**

A：不会自动恢复。关闭开关后**再点一次**「⚡ 立即应用到全部用户」，此时目标值是 `0`，存量用户会被改成不限速。

**Q：管理员会被限速吗？**

A：不会。bot 管理员（`config.admins` 里的 TG ID）与 Emby 侧管理员一律写 `0`（不限速），这个豁免没有开关。

**Q：设成 8 MB/s 之后，Emby 里应该显示多少？**

A：`67108864`（bit/s）。换算见上文「换算规则」。

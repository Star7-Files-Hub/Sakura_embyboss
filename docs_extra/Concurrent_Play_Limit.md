# 同时播放限制检测

## 功能概述

同时播放限制检测功能可以监控 Emby 服务器上所有用户的活跃播放会话，当某个用户的同时播放流数量超过设定值时，自动执行警告、终止所有流、群内通报，并在超过警告次数后自动封禁账号。

## 功能特性

- **播放限制**：设置每个用户允许的同时播放流数量（默认 2 个）
- **自动终止**：超限后强制终止该用户的所有播放流
- **私信警告**：向违规用户发送私信警告
- **群内通报**：违规事件自动发送到配置的主群
- **累计警告**：记录每个用户的警告次数
- **自动封禁**：超过警告阈值后自动封禁账号
- **灵活配置**：所有限制参数均可通过控制面板调整

## 配置说明

在 `config.json` 中添加以下配置项：

```json
{
  "concurrent_play_limit_enabled": false,
  "concurrent_play_limit": 2,
  "concurrent_play_warn_threshold": 3,
  "concurrent_play_check_interval": 60
}
```

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `concurrent_play_limit_enabled` | bool | `false` | 是否启用同时播放限制检测 |
| `concurrent_play_limit` | int | `2` | 每人允许的同时播放流数量 |
| `concurrent_play_warn_threshold` | int | `3` | 警告次数上限，超过自动封禁 |
| `concurrent_play_check_interval` | int | `60` | 检测间隔（秒），建议 30-300 |

## 控制面板操作

在 bot 中输入 `/config` 打开控制面板，找到 **🎬 同时播放限制** 进入设置子面板。

### 设置选项

- **开关同时播放限制**：启用/禁用功能
- **设置播放限制数**：每人允许的同时播放流数量
- **设置警告阈值**：超过此次数将自动封禁
- **设置检测间隔**：检测周期（秒）
- **重置所有警告计数**：一键清零所有用户的警告记录

### 操作示例

```
/config → 🎬 同时播放限制
```

## 工作流程

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 定时检测（按设定间隔）                                      │
│    ↓                                                        │
│ 2. 获取 /emby/Sessions，按 UserId 分组                        │
│    ↓                                                        │
│ 3. 检查每个用户的播放流数量                                     │
│    ↓                                                        │
│ 4. 是否超过限制？                                              │
│    ├── 否 → 跳过                                              │
│    └── 是 → 继续                                              │
│         ↓                                                   │
│ 5. 终止该用户所有播放流（发送消息 + Playing/Stop）               │
│    ↓                                                        │
│ 6. 向用户发送私信警告                                          │
│    ↓                                                        │
│ 7. 在群内发送违规通报                                          │
│    ↓                                                        │
│ 8. 警告计数 +1                                                │
│    ↓                                                        │
│ 9. 警告次数 ≥ 阈值？                                           │
│    ├── 否 → 结束                                              │
│    └── 是 → 封禁用户（禁用 Emby 账号）                          │
└─────────────────────────────────────────────────────────────┘
```

```

您的账号当前有 3 个播放流，超出限制 2 个。
所有播放流已被强制终止。
警告次数: 2 / 3

⚠️ 超过 3 次将自动封禁账号！
```

## 数据库说明

警告计数存储在 `emby` 表的 `concurrent_warn_count` 字段中。当用户被警告时自动递增，封禁后不会自动清零（需手动重置）。

## 注意事项

1. **白名单用户不受限**：建议将管理员账号设为白名单（`lv: a`），避免被误封
2. **检测间隔不宜过短**：建议不低于 30 秒，避免对 Emby 服务器造成压力
3. **与 Emby 原生限制的区别**：Emby 的 `SimultaneousStreamLimit` 策略会在播放开始时拒绝多余流，而本功能是在流已经开始后终止并警告，更适合需要"先播放后警告"的场景
4. **终止流的可靠性**：本功能直接通过 Emby API 发送停止命令，不检查客户端是否支持远程控制，因此可以"强制"终止大部分流

## 与 Tracearr 的配合

如果同时启用了 Tracearr 对接，可以作为终止流的备选方案。但需要注意：

- **EmbyBoss 终止方式**：直接发送停止命令，不检查客户端能力
- **Tracearr 终止方式**：会先检查 `SupportsRemoteControl`，客户端不支持时报错

因此 EmbyBoss 的终止方式更"强力"，Tracearr 的方式更"安全"。
